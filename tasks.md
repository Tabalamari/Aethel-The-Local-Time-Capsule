### Етап 1: Проєктування архітектури та налаштування середовища (Setup & Architecture)
* **Ініціалізація репозиторію та структури проєкту (Monorepo / Client-Server):**
  * Frontend: ініціалізація проєкту на **Angular (TypeScript)** та підключення **Tailwind CSS** для стилізації в атмосферному ретро/мінімалістичному стилі.
  * Backend: ініціалізація сервера на **Node.js + Express** (TypeScript) для кастомної бізнес-логіки, валідації та API.
* **Налаштування Supabase (PostgreSQL + Auth + Storage):**
  * Створення проєкту в Supabase.
  * Налаштування bucket-ів у **Supabase Storage** для збереження фото, відео (до 2–3 хв) та аудіофайлів (для звукової мапи).
* **Проєктування схеми бази даних (PostgreSQL):**
  * `users` (profiles): `id` (UUID, прив'язка до Supabase Auth), `username` (унікальний нікнейм, обов'язковий), `role` (`user`, `partner_guardian`), `created_at`.
  * `locations`: ієрархічна структура або таблиці `countries` → `cities` → `districts` (з можливістю динамічного додавання нових районів користувачами).
  * `media_items` (Daily Snapshots & Vault items): `id`, `author_id`, `location_id`, `media_url`, `media_type` (`photo`, `video`, `audio`), `captured_date` (рік/місяць/день), `caption`, `is_spotlight` (для монетизації), `coordinates` (lat/lng для мапи звуків), `created_at`.
  * `future_letters`: `id`, `author_id`, `location_id`, `title`, `content`, `unlock_date` (дата публічного відкриття, напр., 2050 рік), `is_unlocked`, `created_at`.
  * `vault_settings`: налаштування таймера та дати відкриття головної капсули часу для локацій.
  * `comments`: `id`, `media_id`, `author_id`, `content`, `created_at`.
  * `direct_messages`: `id`, `sender_id`, `receiver_id`, `content`, `is_read`, `created_at`.
* **Налаштування Row Level Security (RLS) та приватності:**
  * Приховування `username` та даних авторів для незареєстрованих користувачів (Guest) на рівні API/RLS.
  * Заборона фільтрації публічної стрічки за конкретним автором для сторонніх користувачів (доступно лише власнику в особистому архіві).

### Етап 2: Автентифікація, ролі та профілі користувачів (Auth & User Privacy)
* **Швидкий вхід / Реєстрація:**
  * Інтеграція Supabase Auth (вхід через Google OAuth та Magic Link на пошту без складних форм).
* **Онбординг і вибір унікального ніка (`Username`):**
  * Модальне вікно / крок після першого входу з перевіркою унікальності нікнейму в реальному часі (debounced API-запит).
* **Розмежування прав Guest vs Registered User:**
  * Реалізація Guards та Interceptors в Angular.
  * Для **Guest**: відображення стрічки, дат і локацій без ніків авторів (`Анонімний мешканець` / приховано), кнопки швидкого входу при спробі коментувати чи завантажити файл.
  * Для **Registered User**: відображення ніків авторів, доступ до завантаження контенту, коментарів, Direct Messages та «Особистого архіву» (де видно лише власні публікації).

### Етап 3: Геолокація та система навігації (Location-based Navigation)
* **Каскадні випадаючі списки (Країна → Місто → Район):**
  * Розробка компонента фільтрації локацій у шапці сайту та на сторінці завантаження.
* **Динамічне додавання локацій:**
  * Можливість обрати «+ Додати новий район/місто» під час завантаження контенту із захистом від дублікатів (нормалізація назв).
* **Фільтрація за часом:**
  * Фільтр за роками та місяцями (Timeline-селектор) для зручного перегляду великої кількості медіа з одного району.

### Етап 4: Головна сторінка, Капсула часу та Контент-модулі (Core Features)
* **Модуль «The Locked Vault & Timer» (Замок і Таймер):**
  * Інтерактивний візуальний компонент цифрового замка на головній сторінці.
  * Таймер зворотного відліку (дні, години, хвилини, секунди) до відкриття загальної капсули часу.
* **Стрічка «Daily Snapshots» (Щоденні знімки):**
  * Компонент завантаження фото та відео (валідація формату, розміру та тривалості відео до 2–3 хвилин через HTML5 Video metadata перед завантаженням).
  * Обов'язкові поля форми: Медіафайл, Локація, Дата створення знімка.
  * Відображення хронологічної стрічки з групуванням за календарними датами та пагінацією (infinite scroll).
* **Модуль «Future Letters» (Листи в майбутнє):**
  * Форма написання текстового послання з вибором дати публічного «відкриття» (unlock date).
  * Логіка блокування: до настання дати відкриття у стрічці відображається лише «Запечатаний лист» (локація, дата написання та таймер до відкриття), а сам текст недоступний на рівні бекенду.
* **Інтерактивна «Мапа звуків та спогадів» (Audio-Geotagging):**
  * Інтеграція інтерактивної мапи (Leaflet / Mapbox).
  * Можливість записати аудіо прямо з браузера (MediaRecorder API) або завантажити аудіофайл і прив'язати його до точки на мапі району.
  * Кастомні маркери «точок звуку» з вбудованим мінімалістичним аудіоплеєром для прослуховування шуму вулиць, прибою чи голосових історій.

### Етап 5: Комунікація та спільнота (Comments & Direct Messages)
* **Публічні коментарі:**
  * Блок коментарів під кожним медіафайлом (доступний для перегляду всім, для написання — лише авторизованим користувачам під їхнім ніком).
* **Приватні повідомлення (Direct Messages):**
  * Можливість натиснути на нік автора або ввести унікальний нік у пошуку, щоб розпочати приватний діалог (наприклад, розпитати деталі про старе фото).
  * Чат-інтерфейс із підтримкою оновлень у реальному часі через **Supabase Realtime**.

### Етап 6: Монетизація та партнерські функції (Monetization)
* **«Підняти на головну» (Sponsored Spotlight):**
  * Виділений блок у верхній частині головної стрічки для закріплених спогадів або локальних привітань.
  * Інтеграція платіжного шлюзу (Stripe / LiqPay / Monobank Acquiring) у тестовому/продакшн режимі для оплати закріплення на певний термін.
* **Статус «Хранитель історії» (Partner Badge):**
  * Спеціальна позначка (бейдж) біля нікнейму та на мапі для локальних кав'ярень і бізнесів, які підтримують проєкт.

---

### Етап 7: Тестування, оптимізація та деплой (QA & Deployment)
* **Оптимізація медіа та продуктивності:**
  * Стиснення зображень на клієнті перед завантаженням (WebP), lazy-loading для фото/відео у стрічці.
* **Тестування безпеки та приватності:**
  * Перевірка витоку ніків авторів для Guest-користувачів через Network-запити.
  * Перевірка недоступності тексту неопублікованих «Листів у майбутнє» через API.
* **Деплой та CI/CD:**
  * Деплой Frontend (Vercel / Netlify) та Backend (Render / Railway), налаштування змінних середовища (`.env`).
